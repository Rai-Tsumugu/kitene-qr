# 90秒デモ台本 r1（まちあわせQR）

- 作成日: 2026-08-29
- 位置づけ: 補足資料。実装コードには触れない。`demo-presentation`工程の下書きとして使う
- 継承元: `requirements-r6.md` §3（90秒デモと画面）、`artifacts/persona-vivid-r1.md`、`artifacts/ui-copy-deck-r1.md`
- 前提: 台本内のNさん・誘い手の心情描写は演出であり、実在Nさんの発言・内心の確認事実ではない（`persona-vivid-r1.md`の境界を維持）

## 更新履歴

- r1: secret入力が必要な`/admin`→`/host/demo`のデモ専用導線を前提に作成。
- r2（本改訂）: `/admin`のデモ専用導線を廃止したため、`/create`（自己申告型イベント作成）を前提に更新。secret入力の工程が丸ごとなくなった。

## 登場人物（2端末・2人）

- 誘い手役: 発表者本人。スマホA（`/create`でイベント作成 → `/host/:inviteId`）
- Nさん役: 補助者。スマホB（QR読み取りから開始、`/invite/:inviteId`）

## 開始前の準備（発表前・タイマー外）

1. スマホAで`/create`を開き、実際のイベント名・日時・待ち合わせ時刻・場所・合図を入力して「イベントを作る」を押す（secret入力は不要）。
2. 送信後そのまま`/host/:inviteId`へ遷移し、QRが表示された状態で待機する。
3. スマホBのカメラアプリまたはブラウザは待機状態にし、まだQRを読み取らない。
4. 発表者はこのイベントの管理linkを`/mine`（約束一覧）から呼び戻せることを覚えておく（画面を閉じても復帰できる）。

## 台本（90秒、実測してタイミング調整すること）

| 時間 | 発表者の動作・セリフ | 画面の動き |
|---|---|---|
| 0-10秒 | 「大学の後輩に、初めての交流イベントを誘ったことがあります。返ってきたのは『まぁ、機会があれば』でした。一人で知らない場に入るのが、たぶんハードルでした。」 | スマホAのQR画面を見せる |
| 10-20秒 | 「これはその一人に向けて作りました。」とスマホAのQRをスマホBのカメラへ向けさせる | スマホBがQRを読み取り、`/invite/:inviteId`へ遷移 |
| 20-30秒 | （何も話さず、スマホBの画面を客席へ見せる） | 「一緒に行ってほしい範囲を選ぶと、誘い手が待ち合わせを確定します（名前や理由の入力は不要です）」の文言と4択が表示される |
| 30-40秒 | Nさん役が「受付まで一緒がいいです」をタップする | スマホBが「依頼中」表示へ遷移 |
| 40-45秒 | 「見送るという選択肢も、他の3つとまったく同じ大きさで並んでいます。断る自由がちゃんとある、というのがここでは大事です。」 | スマホAの画面をカメラで抜く（3秒以内の反映を見せる） |
| 45-55秒 | スマホAに「あなたがすること：17:50に正面入口で待つ（Nさんの希望：受付まで一緒）」が表示される。発表者が「この内容で確定する」をタップ | スマホAが承認操作を行う |
| 55-65秒 | （何も話さず、スマホBの画面を客席へ見せる） | スマホBに「待ち合わせが決まりました。17:50に正面入口で待っています」が3秒以内に表示される |
| 65-75秒 | 「曖昧だった誘いが、具体的な待ち合わせ場所と時刻に変わりました。ここまでが、今回作った一本道です。」 | 両画面を並べて見せる |
| 75-90秒 | 「実際にNさんへ送って参加してもらった、というところまでは今日は検証していません。曖昧な誘いを具体的な合意に変えられるか、という一歩手前までです。」 | 画面を下げ、発表スライドへ戻る |

## 実装済み・mock・未検証の言い分け（発表用の一文）

- 実装済みとして見せてよいもの: QR発行、token交換、role別session、D1保存、2秒polling、再読込後の状態保持、選択→承認→両端末同期、見送り・期限切れ・rate制限の安全な表示。
- mockとして扱うもの: デモイベント名・時刻・場所ラベル・合図はすべてseedの固定値であり、実在の企画情報ではない。
- 未検証として明言するもの: 実在Nさんへ実際に送信したか、実際に参加したか、この体験が参加のハードルを実際に下げたかは未検証。

## Fallback（staging障害時）

`mvp-design-canvas-r5.md`のFallback節に従い、直前に成功した独立2クライアントの録画（有効なQR token・secretは映さない）を使う。録画中に表示される時刻・場所ラベルはseedの固定値であることを一言添える。

## QAチェックリスト（本番前に発表者自身で1回通す）

- [ ] スマホAとスマホBが別browser profile（同一profileの2タブではない）
- [ ] QR読み取りからNさん役の選択まで10秒以内
- [ ] 選択がhostへ3秒以内に反映
- [ ] 承認がNさん役へ3秒以内に反映
- [ ] 両画面をreloadしても状態が残る
- [ ] 見送りを選んだ場合の代替シナリオも1回リハーサルしておく（本番でどちらを選んでも進行できるように）
