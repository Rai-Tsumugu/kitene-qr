# UI文言デッキ r1（まちあわせQR）

- 作成日: 2026-08-29 15:00頃
- 位置づけ: 補足資料。実装中のコードには触れず、画面文言の下書きだけを提供する。採用・変更はCodex側の判断に委ねる
- 継承元: `artifacts/mvp-design-canvas-r4.md`（Screens / Must 5 / Privacy and safety / Fallback）、`artifacts/mvp-design-canvas-r5.md`（Wow moment文言、Evidence handling）
- 方針: 実名・顔画像・大学名・現在地・連絡先・自由記述を一切要求しない。見送りを支援選択と同じ強さで表示する。token・secret・正確な待合せ情報を画面外（ログ・スクリーンショット）へ漏らさない。

## `/join/:inviteToken`（token交換・即303、画面表示なし想定）

- 表示する場合のfallback文（QR不調時にURLを手動で開いたとき）:
  - 見出し: 「招待を確認しています」
  - 本文: 「少しお待ちください」

## `/invite/:inviteId`（participant / Nさん役）

### state: 初回・支援範囲選択前

- 見出し: 「一緒に参加しませんか？」
- 本文（r5 Wow moment原文を正本とする）: 「一緒に行ってほしい範囲を選ぶと、誘い手が待ち合わせを確定します（名前や理由の入力は不要です）」
- 選択肢（`requirements-r6.md` §5 `selected_scope` enumに合わせた4択。同じ強さ・同じサイズで並べ、`今回は見送る`だけ他と区別する強調をしない）:
  - `entrance`: 「入口だけ一緒がいいです」
  - `reception`: 「受付まで一緒がいいです」
  - `first10`: 「最初の10分だけ一緒がいいです」
  - `decline`: 「今回は見送ります」
- 選択肢の下の小さな注記: 「あとから理由を聞かれることはありません」

### state: `requested`（支援を選び、誘い手の承認待ち）

- 見出し: 「誘い手に伝えました」
- 本文: 「誘い手が待ち合わせを確定するまで、少しお待ちください」
- 状態ラベル: 「依頼中」

### state: `confirmed`（誘い手が承認した後）

- 見出し: 「待ち合わせが決まりました」
- 本文テンプレート: 「{時刻}に{場所ラベル}で待っています」
- 補足: 「{合図}」（例: 「青いリュックを背負っています」等、seedで用意した文字列をそのまま表示）
- 下部の小さな注記: 「この画面は再読込しても表示されます」

### state: `declined`（見送りを選んだ後）

- 見出し: 「わかりました」
- 本文: 「今回は見送りとして伝えました。理由を聞かれることはありません」
- 追加のCTAやリンクは置かない（再勧誘しない）

### state: `expired`（410）

- 見出し: 「この招待は期限切れです」
- 本文: 「誘い手にもう一度QRを見せてもらってください」
- 詳細なエラー内容・token情報は表示しない

### state: 429（rate limit）

- 見出し: 「少し時間をおいてください」
- 本文: 「同じ操作が短時間に続きました。1分ほど待ってからもう一度お試しください」

### state: 無効token（404相当）

- 見出し: 「この招待は見つかりません」
- 本文: 「誘い手にQRをもう一度見せてもらってください」
- token文字列や理由の詳細は出さない

### state: 通信失敗

- 見出し: 「通信がうまくいきませんでした」
- 本文: 「電波の良い場所でもう一度お試しください」
- ボタン: 「もう一度試す」

## scope表示名マッピング（participant / host共通）

| `selected_scope` | 表示名 |
|---|---|
| `entrance` | 入口だけ一緒 |
| `reception` | 受付まで一緒 |
| `first10` | 最初の10分だけ一緒 |
| `decline` | 見送り |

hostが承認するときに読み上げる「あなたがすること」の文には、この表示名をそのまま差し込む（例: 「あなたがすること：17:50に正面入口で待つ（Nさんの希望：受付まで一緒）」）。

## `/host/demo`（host / 誘い手役）

### state: `open`（Nさんの回答待ち）

- 見出し: 「Nさんの回答を待っています」
- 本文: 「QRを見せた相手が選ぶと、ここに表示されます」
- QR表示エリアの注記: 「この画面のQRは他の人に見せないでください」

### state: `requested`（Nさんが支援範囲を選んだ）

- 見出し: 「あなたがすること」
- 本文テンプレート（r5 Wow moment・r4本文を踏襲）: 「{時刻}に{場所ラベル}で待つ」
- CTAボタン: 「この内容で確定する」
- 補足: 「Nさんが選んだのは『{選択内容の表示名}』です」

### state: `declined`（Nさんが見送りを選んだ）

- 見出し: 「今回は見送りでした」
- 本文: 「理由は伝えられません。次の機会にまた誘ってみてください」

### state: `confirmed`（承認済み）

- 見出し: 「待ち合わせを確定しました」
- 本文: 「{時刻}に{場所ラベル}でお待ちください」

### state: `expired`

- 見出し: 「この招待は期限切れです」
- 本文: 「管理者にリセットしてもらい、新しいQRを表示してください」

## `/admin`（管理者・デモ運営）

- 見出し: 「デモ管理」
- 本文: 「デモをリセットすると、これまでの招待と選択はすべて無効になり、新しいQRが発行されます」
- ボタン: 「デモをリセットする」
- 確認モーダル: 「本当にリセットしますか？現在の招待・回答は失効します」

## 共通ルール

- どの画面にもtoken文字列、secret、正確な待合せ場所以外の個人情報を表示しない。
- エラー文言は原因の技術的詳細（HTTPステータス名、DBエラー等）を利用者向けには出さない。
- 「見送り」系の文言は常に「支援範囲を選ぶ」系の文言と同じ大きさ・同じトーンにする（review-r3/r4で明記された必須条件）。
- 時刻・場所ラベル・合図はすべてseedデータの差し込み値であり、固定文言に埋め込まない。

## 使い方

- Codexがフロントエンドを実装する際、この文言をそのまま貼る、または表現だけ調整して使う。
- 変更した場合はこのファイルを直接使い捨てにしてよい（正本はCodexが実装したコード側になる）。stateファイルへの反映は不要。
