## C1：入口だけ一緒パス

### Who / Problem / Solution

- **Who**：誘ってくれた先輩とは連絡できるが、初参加の会場へ一人で入ろうとしているNさん。
- **Problem（仮説）**：イベント全体より、建物に入り受付を通る最初の数分が最大障壁で、同行を頼む文章を送るのも気が重い。
- **Solution**：招待URLから「入口だけ一緒」「受付まで一緒」「最初の10分だけ一緒」のどれかをワンタップで頼み、知人が時間を承認する待合せパス。
- **一文**：Nさんの「入口を一人で越える不安」を、知人へのワンタップ同行依頼と確定した待合せで解消する。

### 価値・代替・検証可能な差分

- **価値仮説**：曖昧な「一緒に行こう」ではなく、支援範囲と時刻が確定すると、参加意思を当日の行動へ移しやすい。
- **現在の代替（未確認）**：LINEで同行をお願いする、知人が行ける日まで待つ、入口で一人で迷う、参加しない。
- **差分仮説**：一般的なイベントURLだけを送る場合より、「入口だけ」の小さい依頼ボタンがある方が、日時選択または参加表明まで進む率が高い。
- **最小テスト**：同じイベントで通常招待と同行パス招待を5人ずつに見せ、「押せる／押せない理由」と参加表明率を比較する。

### 90秒MVP導線

1. 先輩がイベント名・日時・入口で会える時間を登録し、招待URLを出す（15秒）。
2. Nさん役がURLを開き、「入口だけ一緒」を選び、候補時刻をタップする（20秒）。
3. 先輩側が依頼を承認する（15秒）。
4. 両端末に同じ色・時刻・場所の待合せカードが出る（10秒）。
5. Nさん役が当日「着いた」を押し、先輩側にも到着状態が反映される（15秒）。
6. 「一人で入口を越える」状態が「会う約束がある」状態に変わったことを示す（15秒）。

### 10秒デモ瞬間

先輩が「承認」を押すと5秒以内に、Nさん側の灰色カードが「17:50、正面入口、青い合図」に変わり、両画面が同じ待合せ状態になる。支援者の操作がNさんの次の行動を確定させる共有変化である。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：Workers + D1、短い招待ID。リアルタイム性はポーリングで十分。Turnstileは公開後の濫用が見えた場合のみ。
- **コスト仮説**：デモ規模はCloudflare無料枠内に収まる可能性が高いが、現行枠はplatformレーンで確認が必要。
- **実装リスク：中**。2端末状態同期、期限切れ、他人による推測アクセスを扱う必要がある。
- **必要調査**：最大障壁が本当に入口か、Nさんが先輩へ頼めるか、先輩が同行を引き受けられるか、位置共有なしで十分か。
- **切るもの**：知らない人との自動マッチング、チャット、地図追跡、プッシュ通知、複数イベント、プロフィール。

## C2：はじめての30秒リハーサル

### Who / Problem / Solution

- **Who**：イベントに少し興味はあるが、会場到着後の流れを想像できないNさん。
- **Problem（仮説）**：受付、着席、自己紹介、休憩など未知の連続を一塊で想像し、「自分にできるか」を判断できず先送りする。
- **Solution**：一番不安な場面を1つ選ぶと、受付から最初の10分までを3択で擬似体験し、自分用の行動台本を持ち帰れる30秒リハーサル。
- **一文**：Nさんの「会場で何が起きるか分からない不安」を、最初の10分だけを先に体験できる30秒リハーサルで小さくする。

### 価値・代替・検証可能な差分

- **価値仮説**：説明文を読むより、自分で3回選んで成功状態まで進む方が、参加後の具体像と自己効力感を持てる。
- **現在の代替（未確認）**：イベント詳細を読む、SNS写真を見る、先輩へ質問する、当日にぶっつけで行く、参加しない。
- **差分仮説**：一般的なFAQより、Nさんが選んだ不安に合わせた「次の一言」付き疑似体験の方が、参加判断と内容理解を促す。
- **最小テスト**：FAQ版とリハーサル版を各5人に触ってもらい、「次に何をするか」の説明正答率と参加意向の変化を測る。

### 90秒MVP導線

1. 招待URLを開き、「いちばん怖いのは？」から「受付で何と言うか」を選ぶ（10秒）。
2. 受付画面で話す一言を3択から選び、スタッフの返答を見る（15秒）。
3. 入室後、座る場所と最初の挨拶を選ぶ（20秒）。
4. 選択結果から「Nさんの最初の10分カード」を即時表示する（10秒）。
5. カードを先輩へ共有し、先輩側には「受付で合流すると安心」の支援ポイントだけが表示される（20秒）。
6. 「未知の90分」が「実行可能な最初の10分」に縮んだことを示す（15秒）。

### 10秒デモ瞬間

Nさん役が不安を1つタップすると5秒以内に、抽象的なイベント案内が「受付でこの一言 → 青い席 → 先輩と合流」の3枚へ変わる。共有時は先輩側に必要な支援1点だけが反映される。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：静的UI + Worker。選択肢と台本はイベントごとの固定テンプレートとし、生成AIは不要。共有する場合のみD1。
- **コスト仮説**：外部API不要のため最小。無料枠の確認はplatformレーンへ渡す。
- **実装リスク：低**。ただし実際のイベント運用と違う台本は逆効果になりうる。
- **必要調査**：未知の流れが障壁か、どの場面が怖いか、主催者から正しい当日導線を得られるか、疑似体験が子どもっぽく見えないか。
- **切るもの**：AI会話、音声、3D会場、イベントページ自動取得、自由入力、全行程シミュレーション。

## C3：最初の10分係

### Who / Problem / Solution

- **Who**：交流そのものには興味があっても、会場で何者として居ればよいか分からないNさん。
- **Problem（仮説）**：目的なく「交流してください」と言われると、話しかける理由も居場所もなく、受け身のまま孤立すると予想して参加を避ける。
- **Solution**：「受付にシールを置く」「最初の質問を1つ選ぶ」「写真の合図を出す」など、最初の10分で終わる役割を1つ予約できる役割カード。
- **一文**：Nさんの「居場所も話す理由もない不安」を、最初の10分だけ誰かに必要とされる小さな役割へ変える。

### 価値・代替・検証可能な差分

- **価値仮説**：交流を目的にするより、短い共同作業を入口にした方が、最初の一人と自然に話しやすい。
- **現在の代替（未確認）**：友人と参加する、主催者に紹介してもらう、会場の端で様子を見る、無理に自己紹介する、参加しない。
- **差分仮説**：肩書きだけの名札より、「10分で完了する具体的役割」がある方が、到着率と最初の会話までの時間を改善する。
- **最小テスト**：役割あり／なしの招待を学生に提示し、選択率と「最初に誰へ何を話すか」の具体性を比較する。

### 90秒MVP導線

1. 主催者役が3つの10分係を公開する（15秒）。
2. Nさん役が招待URLを開き、「質問カードを1枚選ぶ係」を予約する（15秒）。
3. 全員の画面で残枠が2から1へ変わり、Nさんには担当者の顔アイコンと集合場所が出る（10秒）。
4. 会場チェックイン後、担当者と一緒に質問を選び「完了」を押す（25秒）。
5. 役割完了カードに、最初に話した相手と次の自由行動が表示される（15秒）。
6. 「交流しに行く」が「10分の用事をしに行く」へ変わったことを示す（10秒）。

### 10秒デモ瞬間

Nさん役が「この係にする」を押すと、全端末の残枠が変わり、Nさん画面には「あなたを待っている人」と集合場所が出る。Nさんの選択がイベント側の準備状態を変える共有因果を見せる。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：Workers + D1。役割一覧、予約、完了の3状態。QRから参加し、デモでは2端末をポーリング同期。
- **コスト仮説**：デモ規模は低コスト。現行無料枠は未確認。
- **実装リスク：中**。主催者の事前入力が必要で、役割が雑用や圧力に見える危険がある。
- **必要調査**：Nさんは役割がある方が楽か負担か、適切な役割の条件、主催者の準備負担、欠席時の扱い。
- **切るもの**：シフト管理、ポイント、ランキング、複雑な権限、自由記述の役割作成、長時間の担当。

## C4：15分だけ参加パス

### Who / Problem / Solution

- **Who**：少し試したいが、参加表明すると最後まで居続ける責任が生じると感じている可能性があるNさん。
- **Problem（仮説）**：参加／不参加の二択と、途中退出の気まずさが決断コストを上げ、「機会があれば」という保留を生む。
- **Solution**：最初から「15分だけ見て帰ってよい」と退出時刻・助けを求める合図・延長条件を決め、誘った先輩にも共有するお試し参加パス。
- **一文**：Nさんの「参加したら最後まで居なければならない不安」を、退出しても成功になる15分だけの可逆な参加契約へ変える。

### 価値・代替・検証可能な差分

- **価値仮説**：撤退条件を参加前に正当化すると、参加決断の心理的な不可逆性が下がる。
- **現在の代替（未確認）**：「体調が悪くなったら帰る」と自分だけで決める、遅刻して様子を見る、断る、参加後に無理をする。
- **差分仮説**：通常の参加ボタンより「15分だけ」ボタンを先に出す方が、保留中の人の仮参加率を高め、強い後悔を増やさない。
- **最小テスト**：参加／不参加の二択と、15分お試しを含む三択を比較し、選択と理由を記録する。参加後の安心感も必ず確認する。

### 90秒MVP導線

1. Nさん役が招待URLから「15分だけ試す」を選ぶ（10秒）。
2. 「17:45に入口」「18:00に続けるか決める」「帰る時は挨拶不要」を確認する（15秒）。
3. 先輩側が支援条件を承認し、両画面に同じパスが出る（15秒）。
4. 会場でチェックインすると15分タイマーが始まる（10秒）。
5. 終了時に「帰る／あと15分／最後まで」の3択を表示し、「帰る」も緑色の成功として記録する（20秒）。
6. 先輩側にも本人の選択だけが共有され、説得せず支援できることを示す（20秒）。

### 10秒デモ瞬間

「15分だけ」を押すと、参加ボタンが「試せば成功」のパスへ変わり、先輩画面にも「18:00、引き止めない」が表示される。本人の選択が支援者の振る舞いを変える共有体験である。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：Workers + D1。招待、同意、チェックイン、選択の4状態。タイマーはクライアント表示、基準時刻だけ保存。
- **コスト仮説**：外部API不要で低コスト。無料枠は未確認。
- **実装リスク：中**。タイマー表現が急かす可能性があり、主催者が途中退出を本当に許容しなければ成立しない。
- **必要調査**：最後まで居る義務感があるか、15分が適切か、退出保証を誰が出せば信じられるか、途中退出がイベント運営に与える影響。
- **切るもの**：決済・返金、位置情報、自動リマインド、体調推定、参加評価、延長回数の最適化。

## C5：ひとりじゃない不安ボード

### Who / Problem / Solution

- **Who**：交流イベントへ一人で行くことを、自分だけが苦手だと思っている可能性があるNさん。
- **Problem（仮説）**：他の初参加者の不安が見えず、自分だけ場違い・社交性不足だと感じ、参加前に孤立する。
- **Solution**：「入口」「話題」「一人になる」「帰り方」から不安を匿名で1つ投票すると、同じ不安の人数と、それに対する主催者の具体策が同時に見えるボード。
- **一文**：Nさんの「不安なのは自分だけ」という孤立感を、同じ不安の人数と主催者の対応が見える匿名ボードで和らげる。

### 価値・代替・検証可能な差分

- **価値仮説**：人数だけの「初参加歓迎」より、自分と同じ具体的不安と対処が見える方が、安心を現実の行動に結びつけやすい。
- **現在の代替（未確認）**：SNSの参加者投稿を見る、主催者FAQを読む、知人に聞く、不安を隠す、参加しない。
- **差分仮説**：参加人数や「初心者歓迎」の表示より、具体的不安の分布 + 主催対応の組合せの方が、Nさんの参加意向を上げる。
- **最小テスト**：単純な参加人数表示、匿名不安分布、分布 + 主催対応の3画面を比較し、安心理由と参加意向を聞く。

### 90秒MVP導線

1. QRから「初参加で一番気になること」を開く（10秒）。
2. Nさん役が「会場で一人になる」をタップする（10秒）。
3. 全端末の分布が更新され、「同じ不安 4人」と主催者の「初参加席 + 案内役」の対応が開く（10秒）。
4. 別参加者が「話題」を押し、分布と主催対応が再度変わる（15秒）。
5. Nさん役が「この対応なら試せそう」を押し、匿名の参加検討数が増える（15秒）。
6. 主催者側には個人を特定せず、必要な準備の優先順位が出る（20秒）。
7. 不安の可視化が運営の準備を変える因果を説明する（10秒）。

### 10秒デモ瞬間

Nさん役の1票で棒グラフが伸び、「同じ不安 4人」と対応カードが5秒以内に開く。さらに主催画面の準備優先度も「初参加席」に切り替わる。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：Workers + Durable ObjectまたはD1。デモではD1 + 短いポーリングでも成立。匿名のイベント別集計だけを保存。
- **コスト仮説**：低トラフィックなら低コストだが、Durable Objects採用時の料金・制限はplatformレーンで確認が必要。
- **実装リスク：中**。少人数だと匿名性が弱く、票数の水増しや暗い雰囲気、主催者が約束を守らない問題がある。
- **必要調査**：不安の共有が安心か逆効果か、十分な匿名人数、主催者が提供できる対応、投票後に参加行動が変わるか。
- **切るもの**：自由記述、コメント、個人プロフィール、精密分析、AI要約、複数投票防止の強い本人確認。

## C6：名前が分からなくても「あなたに来てほしい」招待

### Who / Problem / Solution

- **Who**：顔は覚えられているが名前を聞き忘れられた程度の関係にある先輩から、イベントを勧められたNさん。
- **Problem（仮説）**：一般的なイベント紹介では、自分が本当に歓迎されているのか、社交辞令なのか、困った時に誰を頼れるのかが分からない。
- **Solution**：誘う人が名前を入力せず、「覚えている場面」「来てほしい理由」「できる支援」を1つずつ選んで送り、Nさんが希望する支援だけ返せる個人招待カード。
- **一文**：Nさんの「自分が本当に歓迎されるか分からない不安」を、名前ではなく覚えている具体的な場面と支援約束で伝える個人招待に変える。

### 価値・代替・検証可能な差分

- **価値仮説**：「興味があればどうぞ」より、相手を覚えている具体的根拠と、頼ってよい範囲が分かる方が、誘いを自分向けとして受け取れる。
- **現在の代替（未確認）**：イベントURLだけ送る、名前を聞き直して個別LINEする、口頭で再度誘う、全員向け告知を送る、そのままにする。
- **差分仮説**：一般招待より「あなたを覚えている理由 + 選べる支援」がある招待の方が、押し付け感を増やさず返信率を高める。
- **独自性仮説**：名前を知らない浅い関係でも個別性を表現する設計に空白がある。既存サービス比較前で未確認。
- **最小テスト**：一般招待文と個人招待カードをNさんに見せ、歓迎感、圧力、返しやすさ、希望支援の選択可否を比較する。

### 90秒MVP導線

1. 先輩役が名前を入力せず、「大学で話した」「一人参加でも大丈夫にしたい」「入口で会える」を選ぶ（20秒）。
2. 生成された短い招待カードをURLで送る（10秒）。
3. Nさん役がカードを開き、「覚えていてくれた理由」と支援候補を見る（15秒）。
4. 「入口で会ってほしい」を押す（10秒）。
5. 先輩側の画面が、曖昧な招待済みから「17:50に入口で会う」という具体的約束へ変わる（15秒）。
6. 両者の画面に、断っても理由不要の選択肢が残ることを示す（10秒）。
7. 「おすすめした」から「この一人を迎える約束をした」への変化を示す（10秒）。

### 10秒デモ瞬間

Nさん役が「入口で会ってほしい」を押すと、先輩側の招待カードが即座に「あなたがすること：17:50に入口へ」に変わる。Nさんの返答が、誘った人の責任ある次行動を生む。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：Workers + D1または短命KV。テンプレート選択式で外部AI不要。推測困難な招待トークンと期限を設ける。
- **コスト仮説**：低コスト。無料枠とKV/D1の選択はplatformレーンで確認する。
- **実装リスク：低〜中**。個別性が監視感・圧力に変わる危険、名前を知らないことの失礼さ、招待URL漏えいがある。
- **必要調査**：Nさんが誘いを社交辞令と感じたか、歓迎感が障壁か、どの具体情報なら気味悪くないか、断りやすさが守られるか。
- **切るもの**：顔画像・顔認識、連絡先検索、自由文AI生成、既読通知、追いかけ通知、SNS自動投稿。

## C7：最初の一人とつながる合図

### Who / Problem / Solution

- **Who**：会場まで来ても、誰に何を話しかければよいか分からず入口付近で止まりそうなNさん。
- **Problem（仮説）**：知らない相手への最初の声かけには、相手が話してよい状態か、共通点があるか、何を聞けばよいかの3つが不足する。
- **Solution**：到着時に関心を1つ選ぶと、会場内の案内役1人に同じ色と記号を出し、両画面に同じ「最初の一問」を表示する合図。
- **一文**：Nさんの「誰にどう話しかけるか分からない不安」を、会場で一致する合図と両者に開く最初の一問で解消する。

### 価値・代替・検証可能な差分

- **価値仮説**：ランダムな交流より、話しかけてよい相手が物理的に見つかり、同じ問いを見ていると最初の声を出しやすい。
- **現在の代替（未確認）**：主催者に紹介してもらう、名札を見る、近くの人に声をかける、知人の後ろについて行く、話さず帰る。
- **差分仮説**：通常の名札や趣味タグより、「今この相手とこの一問」の一時的な合図の方が、チェックインから最初の会話までの時間を短くする。
- **最小テスト**：名札だけの状態と合図 + 一問の状態で、初対面ペアが会話開始するまでの時間と気まずさを比較する。

### 90秒MVP導線

1. 案内役が会場モードを開き「受け入れ可能」にする（10秒）。
2. Nさん役がQRから「ものづくりの話」を選び、チェックインする（15秒）。
3. Nさんと案内役の両画面に「青い三角」と集合地点が同時に出る（10秒）。
4. 2人が同じ合図を確認し、「会場に来た理由は？」という最初の一問を開く（15秒）。
5. どちらかが「話せた」を押すと合図が完了し、次の初参加者を受け入れられる状態になる（15秒）。
6. 別の参加者操作で案内役の表示が変わり、共有状態が循環することを見せる（20秒）。
7. 一人で会場に居る状態が、最初の一人と一問を共有する状態へ変わったことを示す（5秒）。

### 10秒デモ瞬間

Nさん役が関心を押すと、Nさんと案内役の2画面が同じ「青い三角」と一問へ切り替わる。初参加者の入力が、会場にいる相手の次行動を直接変える。

### 公開Web / Cloudflare適合、コスト、リスク

- **構成**：Workers + Durable Objectが自然だが、2時間MVPではD1 + ポーリング、案内役固定1人で代替できる。QRと2端末が必要。
- **コスト仮説**：小規模デモは低コストの可能性が高いが、リアルタイム構成と現行料金は未確認。
- **実装リスク：中〜高**。現地案内役、2端末同期、取り違え、安全性、待ち時間、案内役不在時のfallbackが必要。
- **必要調査**：Nさんが合図を使う恥ずかしさ、主催者が案内役を置けるか、色覚・アクセシビリティ、合図で本当に会話開始できるか。
- **切るもの**：参加者同士の自動マッチング、位置追跡、顔写真、自由チャット、複数同時ペア、推薦AI、ランキング。

## Fan-inへ渡す比較観点

採用判断はこのレーンでは行わない。`similar-service-research` と市場調査の結果を受け、少なくとも次を同じ尺度で確認する。

1. Nさん本人が「一人で行けない」のどの瞬間を最大障壁として挙げるか。
2. 解決後に測る行動が、返信、仮参加、来場、入場、最初の会話のどれか。
3. 支援者または主催者の協力が現実に得られるか。
4. 既存のLINE、イベントFAQ、Peatix等の参加者機能、主催者の手作業に対する検証可能な差分があるか。
5. 90秒で「開始状態 → Nさんの操作 → 他者側の変化 → 問題が小さくなる」を2端末または独立クライアントで実演できるか。
6. 個別性が歓迎ではなく圧力・監視・安全リスクにならないか。
7. Cloudflare上の公開URLで、外部AIや実在ユーザー登録なしに主要価値を再現できるか。
