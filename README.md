# きてねQR生成（まちあわせQR）

「きてねQR生成」は、初めてのイベントへ一人で参加する不安を、具体的な待ち合わせの約束に変えるためのWebアプリです。画面上では「まちあわせQR」という名前で表示されます。

誘う側がイベントと待ち合わせ情報を入力してQRコードを作り、参加する側はQRコードを読み取って「どこまで一緒に行ってほしいか」を選びます。誘う側が内容を確認すると、両方の画面に同じ待ち合わせ内容が表示されます。

## できること

- イベント名、開催日時、待ち合わせ時刻・場所、合図を入力して招待を作る
- 参加者用のQRコードとURLを発行する
- 参加する側は、名前や理由を入力せずに希望を選ぶ
  - 入口だけ一緒
  - 受付まで一緒
  - 最初の10分まで一緒
  - 今回は見送る
- 回答を誘う側の画面へ自動で反映する
- 誘う側が待ち合わせを確定し、両者に同じ確認内容を表示する
- このブラウザで作成・参加した約束を「約束一覧」から確認する
- 過去のイベントをテンプレートにして、次の招待を作る

## 使い方

### 1. 誘う側がQRコードを作る

1. トップページで「自分のイベントを作る」を押します。
2. 次の内容を入力します。
   - イベント名
   - 開催日時
   - 待ち合わせ時刻
   - 待ち合わせ場所
   - お互いを見つけるための合図
3. 「イベントを作る」を押します。
4. 表示されたQRコードを、参加してほしい相手のスマートフォンへその場で見せます。

QRコードには招待用のURLが含まれます。招待を受ける本人以外へ共有したり、SNSへ掲載したりしないでください。

### 2. 参加する側が希望を選ぶ

1. スマートフォンのカメラなどでQRコードを読み取ります。
2. 表示されたイベント名と日時を確認します。
3. 「入口だけ一緒」「受付まで一緒」「最初の10分まで一緒」「今回は見送る」から1つ選びます。

アカウント登録、名前、参加理由、見送る理由の入力はありません。一度送信した回答は変更できません。

### 3. 誘う側が待ち合わせを確定する

1. 参加する側の回答が、誘う側の画面へ自動で表示されます。
2. 待ち合わせ時刻と場所を確認し、確定ボタンを押します。
3. 誘う側・参加する側の両画面に、時刻、場所、合図、一緒に行く範囲が表示されたら完了です。

「今回は見送る」が選ばれた場合は、理由を表示せず、その回答で終了します。

## 約束一覧について

「約束一覧」には、この端末のブラウザで作成または参加した約束が保存されます。

- 一覧の情報はブラウザ内にだけ保存され、別の端末には同期されません。
- 相手の呼び名を任意でメモできます。このメモもサーバーへは送信されません。
- 作成した約束は、待ち合わせ時刻・場所・合図をテンプレートとして再利用できます。

## 利用時の注意

- 招待の有効期限は作成から2時間です。
- 誘う側・参加する側の操作用セッションは最長1時間です。
- QRコードは作成直後の画面でのみ表示されます。相手が読み取る前に画面を再読み込みしないでください。
- QRコードの代わりにURLを渡す場合は「fallback URLをコピー」を使えますが、QRコードと同じく招待を受ける本人だけに共有してください。
- 再読み込み後も「約束一覧」から誘う側の管理画面へ戻れますが、参加者用QRコードは再表示できません。必要な場合は新しい招待を作ってください。
- 1つの招待に対して、参加する側の回答は1回だけです。複数人への一斉招待には対応していません。
- 通知、地図、カレンダー連携、到着確認、アカウント管理はありません。

## プライバシーと安全性

- 参加する側の名前、連絡先、位置情報、自由記述は収集しません。
- 招待トークンとセッショントークンは、サーバーではハッシュ化して保存します。
- 操作には有効期限付きのCookieを使い、招待画面はキャッシュしない設定です。
- イベント情報、待ち合わせ情報、回答状態は、両者の画面を同期するためCloudflare D1へ保存します。
- 短時間に繰り返される操作には回数制限があります。

## 開発環境で動かす

アプリ本体は `app/` にあります。Node.js、npm、Cloudflare Wranglerを利用します。Wranglerは依存関係としてインストールされるため、別途グローバルインストールする必要はありません。

```bash
cd app
npm ci
cp .dev.vars.example .dev.vars
```

`.dev.vars` の `DEMO_ADMIN_SECRET` に、ローカル環境専用の推測されにくい値を設定してください。この値は管理用デモのE2Eテストで使います。公開環境の値を流用しないでください。

続いて、ローカルD1の準備、フロントエンドのビルド、開発サーバーの起動を行います。

```bash
npm run db:migrate:local
npm run build
npm run dev
```

起動後、<http://localhost:8787> を開きます。

## 検証

型チェック、ユニットテスト、プロダクションビルドをまとめて実行します。

```bash
cd app
npm run check
```

開発サーバーを起動した状態で、別のターミナルから管理用デモ導線を含むローカルE2Eテストを実行できます。

```bash
cd app
sh test/local-e2e.sh
```

## 主な構成

```text
app/
├── src/main.ts           # ブラウザ画面と操作
├── src/worker.ts         # API、認証、招待状態の管理
├── src/core.ts           # トークン生成などの共通処理
├── migrations/           # Cloudflare D1のスキーマ
├── test/                 # ユニットテストとローカルE2E
└── wrangler.jsonc        # Cloudflare Workers / D1設定
artifacts/                # 設計・検証記録
presentation/             # 発表資料
prototype/                # 初期UIプロトタイプ
```

## 技術構成

- フロントエンド: TypeScript、Vite
- API: Hono on Cloudflare Workers
- データベース: Cloudflare D1
- QRコード生成: `qrcode`
- テスト: Vitest、ローカルE2Eスクリプト

## 現在の位置づけ

このアプリは、交流イベントなどへの初参加を後押しする最小構成のMVPです。「一人で行く不安」が実際に解消されるか、イベント参加につながるかといった効果は、利用者への検証が必要です。
